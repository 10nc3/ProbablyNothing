1. context-router.js — Hardcoded path breaks everywhere except your Mac
jsconst WORKSPACE = '/Users/enoch/.openclaw/workspace';
This kills portability. On Replit, cloud, or anyone else's machine, every readFile call silently returns null. Use process.env.WORKSPACE_PATH || process.cwd() or resolve relative to __dirname.
2. void-pipeline.js — Nyan API called on EVERY query before LLM
js// General atomic query fallback
if (!response) {
  const result = await atomicQuery(query);
  ...
}
Every single query hits the Nyan API first, even "hello" or "what's the weather." This adds latency to every request and wastes API calls. The Nyan API should only fire when intents match (stock, psi-ema, legal) — not as a general-purpose step.
3. llm-client.js — callWithFallback ignores system prompt
The pipeline passes { system: systemPrompt } but callLLM and all provider functions only accept prompt as a string and options for model/temperature. The system prompt is silently dropped — your entire expert context, memory, and personality injection never reaches the LLM. This is the most damaging bug.
4. llm-client.js — MiniMax has hardcoded fallback to Ollama inside callMiniMax
js} catch (e) {
  return await callOllama(prompt, options);
}
This bypasses callWithFallback's chain logic entirely. If MiniMax fails, it jumps straight to Ollama, skipping Groq/Claude/OpenAI. The fallback chain in env-detect.js becomes decorative.
5. whatsapp-cc.js — requires nonexistent module
jsconst { message } = require('./tool-adapters.js');
tool-adapters.js wasn't uploaded and isn't referenced anywhere else. This will crash on import. If it's an OpenClaw runtime dependency, it should be guarded with a try/catch.
6. index.js (lib) — exports nonexistent function
jsdetectMode: require('./mode-registry').detectMode,
mode-registry.js exports detectCodeMode, not detectMode. The actual detectMode lives in void-pipeline.js. This will throw at runtime if anything calls lib.detectMode().

Significant Issues
7. memory-manager.js — uses PLAYGROUND_GROQ_TOKEN for summarization, not the main GROQ_API_KEY
The memory summarizer checks process.env.PLAYGROUND_GROQ_TOKEN but env-detect and llm-client use GROQ_API_KEY. If you only set GROQ_API_KEY, memory summarization silently fails. Inconsistent env var naming.
8. void-pipeline.js — privilege check has phone number in source
jsconst PRIVILEGED_NUMBER = '+628116360610';
Same issue as AGENTS.md. Should come from env.
9. data-package.js — setInterval cleanup timer runs forever
The DocumentExtractionCache and the session cleanup in memory-manager.js both set up intervals. These prevent clean process shutdown and will keep Node alive even after your server closes. Use unref() consistently (you do it for one but not the others in memory-manager).
10. void-pipeline.js — memory updated AFTER response, but summary may trigger mid-flow
shouldSummarize() increments queryCount but is never called in the pipeline. The summary generation path (generateSummary) is defined but never invoked anywhere. The φ-compressed memory system is wired up but not connected.

Design Observations
11. The fallback chain is documented in 3 places with slight differences. env-detect.js builds it dynamically, llm-client.js hardcodes [MINIMAX, OLLAMA], and model-fallback.js has its own independent chain via the OpenClaw gateway. Only env-detect.js's chain is correct, but llm-client.js ignores it entirely — it never receives the chain from env-detect.
12. No Express server file. package.json lists Express, helmet, cors, sessions, rate-limit, and pg — but there's no server/app file that wires up routes (/api/chat, /api/atomic, etc.). Either it wasn't uploaded or it doesn't exist yet.
